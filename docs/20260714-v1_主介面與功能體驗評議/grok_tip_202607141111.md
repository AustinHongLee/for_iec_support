## 1. 十行內總評

這不是「缺功能的半成品」，而是**功能已堆進同一畫面、但狀態模型沒有收斂成一條可執行工作流**的桌面工具。  
G4e 之後，匯入引導、主表＋BOM、角色欄、逐欄篩選、覆寫 debounce 重算、材質進度、數據維護門檻都「有」；使用者仍不爽，是因為**有功能 ≠ 知道現在在哪一步、下一步按哪、畫面上的數字能不能信**。  
最嚴重的不是配色，而是三個**產品語意錯誤／半套規則**：  
（1）「材質確認 N/M」在匯入後預設幾乎永遠滿格——它量的是「沒被標成未定」，不是「已人工確認」；  
（2）全域材質變更只改設定、**不重算也不使結果過期**，匯出仍可能帶舊數字；  
（3）清單結構變更要手按分析，覆寫變更卻先清空全表再自動重算——同一「輸入變了」有兩套物理法則。  
次嚴重是**雙來源＋三處明細**（左可編輯清單、中唯讀主表、右覆寫＋又一份計算結果 HTML，外加 BOM 面板），選取連動依賴 project index，但 `_results` 與明細 `group_key` 在「有停用列」時用的是 enabled 序——這是實作層的可驗收缺陷，不是品味問題。  
因此本輪建議：**先修狀態真值與完成度語意，再收資訊架構；不要再加 Tab、不要移除左清單、不要重寫。**

## 3. 建議的資訊架構

### 原則

1. **單一編輯源**：左清單（現階段）= 唯一可改輸入；主表 = 分析投影。  
2. **單一結果真值**：`_project_result` 在「新鮮」時才驅動 KPI／主表／BOM／匯出；stale 時全部降級顯示，禁止半新半舊。  
3. **單一待辦入口**：問題佇列，不散落三個按鈕。  
4. **右欄是選取筆的工具**，不是第二張結果總表（計算結果 Tab 與 BOM 面板職責重疊，應收斂）。

### 各區責任

| 區 | 責任 | 禁止 |
|---|---|---|
| 標頭 | 清單名、全域材質、模式、**真實**待辦數、資料版本、匯出就緒 | 複製一份 KPI 總重 |
| 左 | 匯入／貼上／啟用／刪修／存檔 | 顯示計算總重當主核對面 |
| 中摘要 | 總重／成功／錯誤；stale 時整條警告 | 當教學文案牆 |
| 中主表 | 一列一筆掃描與篩選 | 沉默的第二編輯器 |
| 中 BOM | 選取筆零件 | 專案匯出 |
| 右 | 覆寫＋圖面（可折疊）＋本筆警告 | 與 BOM 重複的完整表（可改「差異／警告」） |
| 匯出列 | 格式、匯出、完成檢查 | 分析（分析留左或標頭） |

## 6. 四個爭議題的明確立場

### 6.1 左側輸入清單去留

**留。現在刪是錯的。**

| 條件 | 狀態 |
|---|---|
| 主表可編輯 Drawing／流水號／數量／型號／啟用 | 未 |
| 多選批次材質在主表 | 未（在左清單右鍵） |
| 鍵盤 Delete／F2 | 綁在左清單 |
| 使用者完成一專案週期後明確同意 G4b-2 | STATUS：未 |

過渡可做：左欄預設寬度縮小、提供「專注結果」暫時折疊，**不是移除資料模型上的編輯源**。

### 6.2 搜尋與逐欄篩選

| | 尋找 | 欄位條件 |
|---|---|---|
| 問題 | 「這字串在哪」 | 「只要這個 Drawing／型號／狀態」 |
| 控制 | 單一 QLineEdit + Ctrl+F | 每欄一個，值來自 `filter_options` |
| 組合 | 與條件 AND | 與尋找 AND |
| 不要 | 再做第三個「智慧搜尋」 | 假裝已是 Excel 表頭 Autofilter 卻無多選勾選 |

「僅看待確認」應是待辦佇列的視圖，不是第五種篩選品牌。

### 6.3 自動重新分析：回饋與撤銷

**保留自動重算，但必須變成可觀察、可撤銷、全入口一致。**

| 階段 | 必要回饋 |
|---|---|
| dirty/stale | 摘要條：「結果已過期」；匯出禁用 |
| busy | 按鈕「分析中...」、游標、側欄 busy（已有部分） |
| done | 筆數＋錯誤數；**本筆 Δ總重**；選取維持 |
| error | 維持 ✗ 與 dialog（分析例外） |
| undo | 還原 overrides／批次前快照 → 再走同一重算 |

**禁止**：invalidate 清空畫面造成 700 列「閃空白」卻無「即將重算」說明——應改 **保留舊結果但打過期水印**，重算成功再替換（體感會好一個數量級）。

### 6.4 數據維護：使用者與權限

| | 規定 |
|---|---|
| 使用者 | 維護基準資料的工程負責人；非日常 MTO 作業員 |
| 可改 | `EDITABLE_SCALAR_FIELDS` + `table` 儲存格 |
| 不可改 | 結構／公式／designation 規則（唯讀 Tab 正確） |
| 必填 | 圖號+版次、說明；sanity 大幅變動確認；存檔前 diff 確認框——**全留** |
| 存檔後 | 必須能打斷分析頁的「舊結果可信」幻覺 |
| 不做 | 多人審批、自動改 golden、任意 JSON 鍵編輯 |

## 7. 不建議做的事

1. **現在執行 G4b-2 移除左清單** — 編輯能力尚未遷移。  
2. **網頁化／AI 助手／Dashboard 重寫** — 不解決狀態機與完成度說謊。  
3. **把角色 preset 拆成三個主頁** — 複製狀態，無益。  
4. **每個覆寫彈「是否重算」** — 與自動重算目標相反；改用可 Undo。  
5. **再加第四套「狀態」視覺體系** — 先統一 ✓⚠✗— 與 stale。  
6. **維護頁開放公式/結構** — 可追溯與安全底線。  
7. **用改計算真值來遷就 UI** — 違反 AGENTS。  
8. **雙向大編輯（左＋主表同時可改）且無 single source of truth** — 必炸。  
9. **在完成度語意修正前大做「待辦遊戲化」** — 會建立在錯誤指標上。  
10. **匯出再加三道無資訊量的 Yes/No** — preview 已夠；缺的是日常可見的完成燈，不是更多 dialog。

## 8. 分階段路線圖

### 立即修正（缺陷與語意，1 波可驗收）

1. 材質完成度語意裁決並改 UI／測試。  
2. 全域材質 → stale + 重算。  
3. project/result index 全路徑對齊。  
4. 空狀態、按鈕/狀態列文案一致。  
5. stale 橫幅；重算中/過期禁匯出。  
6. 右欄重選保留 Tab；結果改走 `_row_result_for_project_index`。

### 下一波結構（工作流收斂）

1. 統一自動重算法則；stale 時保留舊結果水印優於閃清空。  
2. 待處理佇列。  
3. 本筆 Δ總重 + Undo stack。  
4. Preview 問題列。  
5. 維護存檔 → 分析 stale。  
6. 圖面預設折疊；篩選 chip。

### 具備資料／真實使用後

1. 專案檔（清單+模式+覆寫+結果指紋）與最近開啟。  
2. config 版本比對重算。  
3. change_log 瀏覽/回復。  
4. 主表編輯 → 再評估移除左清單。  
5. 個人篩選/欄寬記憶；BOM 前後 diff。

## 9. 需要使用者回答的問題

1. **匯入 MTO 後，上段管材質預設應是「全部未定待確認」還是「先用全域材質當已確認概算」？**（決定完成度演算法；這是產品決策不是 UI 口味）  
2. 實務上是否常**停用**部分列再分析？（決定 index 修復的優先緊急度；有的話是現在就壞）  
3. 改完單筆覆寫，你能否接受 **0.5–1s 全量重算**（704 列實測 ~0.6s），還是必須改增量重算？  
4. 交件定義：精算是否**必須**零 assumption，還是例外放行是常態？  
5. 左清單與主表並存，你是否真的兩邊都在用，還是其中一個可以「折疊預設關」？  
6. 數據維護是否僅你一人？要不要「只讀不能存」？  
7. 「全部明細」過去實際使用頻率？  
8. 貼上多筆與 Excel 匯入的使用比例？

## 10. 最終只選五項

若資源只夠五件事，**嚴格按此序**：

| 序 | 項 | 為什麼是前五，不是第六 |
|---|---|---|
| 1 | **修正材質確認／待辦語意** | 現在所有「完成度」「僅待確認」「核對模式」都可能建立在空集合上；不修則後面佇列、匯出燈全是假的 |
| 2 | **全域材質 + 所有輸入變更走同一 stale/重算／禁匯出狀態機** | 這是「改完有沒有重算」抱怨的根；只補側欄文案無效 |
| 3 | **project/result index 對齊** | 這是正確性 bug；UX 再漂亮也會看錯筆 |
| 4 | **空狀態 + 完成檢查可見化（接既有 export preview 語意）** | 解決第一步與最後一步；成本低、每天都碰到 |
| 5 | **本筆 Δ總重 + 工作階段 Undo** | 讓自動重算從威脅變成工具；否則使用者會不敢用右側修正 |

**刻意沒進前五**：最近專案、獨立預檢中心、個人 preset、維護附件審批、移除左清單、右欄重做、AI——那些要嘛依賴前五，要嘛是在逃避狀態模型。
