# 給 Grok／DeepSeek／Opus 的共同評議 Prompt

你是這個工程桌面軟體的外部產品設計審查者。請以「第一次接觸此工具、但熟悉 Excel 與工程清單的使用者」角度，獨立評議目前介面與工作流程。

你的任務是提出可裁決、可驗收的意見，不是直接修改程式。不要迎合既有設計，也不要為了顯得有創意而堆功能。

## 專案與使用情境

這是一套 Windows／PyQt6 的 IEC 管架支撐分析工具。典型工作包含：

1. 從 Support MTO Excel、CSV、標準範本或貼上資料建立支撐清單。
2. 依 Drawing、流水號、Type、數量等資料分析重量與 BOM。
3. 處理材質未定、Type 覆寫、查表值覆寫與概算／精算狀態。
4. 在主表檢視支撐結果，在明細區核對 BOM。
5. 需要時維護 Type 的已確認常數與查表資料。
6. 通過確認條件後匯出 Excel 結果供工程、採購與查核使用。

使用者對目前介面的主要不滿不是配色，而是：資訊擁擠、功能責任不清、下一步不明顯、輸入與匯入的概念抽象、搜尋價值低，以及修改後是否已重新分析不夠直覺。

## 必須評議的五條工作流

### A. 開始工作與建立輸入

- 第一次開啟時，使用者是否知道該拿什麼檔案、缺什麼欄位、匯入後會發生什麼？
- 左側輸入清單目前應保留、縮成摘要、改成抽屜，還是等主表可完整編輯後移除？
- 貼上、單筆新增、Excel／CSV 匯入、載入已存清單之間的關係是否清楚？

### B. 分析結果與尋找資料

- KPI、主表、BOM 明細、完整明細與右側設定區的視覺優先序是否正確？
- 文字搜尋與 Excel 式逐欄篩選應如何分工？
- 工程／採購／查核視圖應是欄位 preset、角色模式，還是不同頁面？

### C. 修正、確認與自動重新分析

- 使用者如何知道目前選了哪一筆、改了什麼、正在重算、重算完成、結果變了多少？
- 單筆修改、批次修改、材質確認與下一筆待確認之間應如何串成連續工作流？
- 自動重新分析需要哪些 busy、成功、錯誤與撤銷回饋？

### D. Type 數據維護

- 這個頁面真正的使用者是誰？哪些欄位可以安全直接改，哪些必須保持唯讀？
- 自動差異、驗證、圖號／版次、變更說明與 golden 驗證提示的順序是否合理？
- 是否還缺變更歷史、來源附件、草稿、審批、版本回復或影響範圍預覽？若建議增加，必須說明最小可行版本與避免誤用的方法。

### E. 專案狀態、完成與匯出

- 使用者如何一眼確認「輸入完整、分析完成、材質已確認、可以匯出」？
- 概算／精算、例外匯出與資料版本足跡是否應集中成一個完成檢查區？
- 匯出後應提供哪些結果、警告或可追溯資訊？

## 請特別討論的候選功能

以下是候選題，不代表都該做。請逐項給出「現在做／稍後做／不建議」及理由：

1. 專案首頁或最近使用檔案、未完成工作續接。
2. 匯入前預檢中心：欄位對應、缺漏、重複、跳過列與修正建議集中顯示。
3. 可儲存的篩選／欄位視圖 preset。
4. 單筆與批次修改的 Undo／Redo 或本次工作階段變更紀錄。
5. 統一的「待處理問題」佇列，串接材質未定、匯入缺漏、分析錯誤與覆寫待確認。
6. 修改前後重量／BOM 影響比較。
7. 專案使用舊 Type 資料版本時的影響提示與重新計算選項。
8. Type 數據維護的變更歷史、版本回復與來源附件連結。
9. 大型清單的鍵盤操作、固定欄、欄寬／排序記憶與效能回饋。
10. 將右側圖面、修正、結果、邏輯改成抽屜、分頁、獨立視窗或情境面板。
11. 你認為比上述項目更值得做的 1–3 項功能。

## 評議約束

- 不得改動或重新詮釋 BOM、重量、材質、尺寸與 Type 計算真值。
- 不得用「改成網頁版」「加 AI 助手」「全面重寫」逃避目前 Windows 桌面工具的設計問題；若提出，必須證明它解決的問題不能用較小改動處理。
- 不得只說「簡化、現代化、增加提示、優化 UX」。每個建議至少包含目前問題、建議行為、使用者得到的回饋與驗收方式。
- 必須區分表面排版問題、資訊架構問題、狀態／流程問題與缺少功能，不能把所有問題都歸類成 UI 美化。
- 優先保護工程可追溯性與防誤操作；同時避免為了安全把所有動作塞進確認對話框。
- 請明確列出不該做的功能及理由。

## 固定輸出格式

請以繁體中文撰寫，並嚴格使用以下章節：

1. `# <模型名稱>｜主介面與功能體驗獨立評議`
2. `## 1. 十行內總評`
3. `## 2. 五條工作流逐項診斷`
   - 用表格列：工作流、目前摩擦、根因層級、建議行為、嚴重度、證據。
4. `## 3. 建議的資訊架構`
   - 說明主畫面各區責任，附一個精簡 ASCII wireframe。
5. `## 4. 前十項改動優先序`
   - 用表格列：排名、改動、使用者價值、實作成本 S/M/L、風險、依賴、可驗收條件。
6. `## 5. 候選功能裁決`
   - 對上述 11 類功能逐項判定：現在做／稍後做／不建議。
7. `## 6. 四個爭議題的明確立場`
   - 左側輸入清單去留。
   - 搜尋與逐欄篩選的分工。
   - 自動重新分析的回饋與撤銷。
   - 數據維護頁的目標使用者與權限邊界。
8. `## 7. 不建議做的事`
9. `## 8. 分階段路線圖`
   - 立即修正、下一波結構調整、具備資料後再做。
10. `## 9. 需要使用者回答的問題`
11. `## 10. 最終只選五項`
    - 如果只能做五件事，列出順序與理由。
