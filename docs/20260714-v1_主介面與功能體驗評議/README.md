# 2026-07-14 v1｜主介面與功能體驗評議

## 目的

邀請 Grok、DeepSeek、Opus 以相同現況、相同問題與相同輸出格式，獨立評議 IEC 管架支撐分析工具的主介面、數據維護頁與端到端操作流程。

這一輪只產生產品與 UX 意見，不直接修改程式、計算公式、Type 資料或測試基線。三份意見收齊後，再由使用者與 Codex 做交叉比較及裁決。

## 檔案

- `PROMPT_主介面與功能體驗評議.md`：交給三個模型的共同 prompt。
- `grok_tip_202607141111.md`：Grok 的獨立意見。
- `deepseek_tip_202607141111.md`：DeepSeek 的獨立意見。
- `opus_tip_202607141111.md`：Opus 的獨立意見。
- `綜合比較與裁決表.md`：三份回覆收齊後才填寫，避免先入為主。

## 使用方式

1. 三個模型都使用完全相同的 `PROMPT_主介面與功能體驗評議.md`。
2. 若模型能讀本機 repo，要求它先讀 prompt 指定的現況檔與程式碼；若不能，至少附上同一批操作截圖及 `docs/STATUS.md`。
3. 模型只能填寫自己的 `*_tip_*.md`，不可先閱讀其他模型的意見。
4. 第一輪禁止實作，禁止用「介面現代化、增加 AI、做成 dashboard」等空泛句子代替具體流程分析。
5. 三份意見收齊後，才填 `綜合比較與裁決表.md`，將共識、衝突與使用者裁決分開記錄。
