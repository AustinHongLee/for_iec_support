## 欄位順序建議

### 現狀問題

[程式] UI 結果表格目前順序為「型號 → 組數 → 項次 → 品名…」，使用者的不滿很具體：「組數」和「單件數量」中間隔了 5 個欄位，讀者無法一眼看出 `單件數量 × 組數 = 總數量`。

[程式] Excel PROJECT_HEADERS 也是同樣問題：型號、組數、項次、品名、規格、材質、長度、寬度、單件數量、單件重量…總數量 — 組數和單件數量中間隔了 6 欄。

### 建議 UI 欄位順序

```
型號 / 項次 / 品名 / 規格 / 材質 / 長度 / 寬度 /
單件數量 / 組數 / 總數量 / 單組重 / 總重 /
屬性 / 物件類別 / 製造方式 / 計算說明 / 零件ID / 庫存ID
```

變動：
1. **組數移到單件數量右邊** — 視覺上形成 `單件數量 × 組數 = 總數量`
2. **項次移到型號之後** — 品名之前，邏輯上是「型號下的第幾項」
3. **零件ID / 庫存ID 移到最後** — 內部用欄位，長官不需要看到

### 建議 Excel `計算依據` sheet 欄位順序

```
型號 / 項次 / 品名 / 規格 / 材質 /
長度 / 寬度 / 屬性 / 物件類別 / 製造方式 /
單件數量 / 組數 / 總數量 / 單件重(kg) / 單組重(kg) / 合計重(kg) /
計算式 / 可信度 / 來源依據
```

變動：
1. **組數移到單件數量右邊**（同 UI）
2. **總數量插入單組重之前** — 三欄排在一起
3. **可信度 / 來源依據移到最後兩欄**（見下一節處理建議）
4. **計算式移到重量欄位之後** — 重量欄是主體，計算式是補充

[推測] `單件重` 和 `單組重` 容易混淆：`單件重` 是一塊板的重量，`單組重` 是該項次所有板的重量（單件重 × 單件數量）。建議加注或改為 `單件重(kg)` / `本項小計(kg)`。

## 「可信度 / 來源依據」處理建議

### 現狀

[程式] `計算依據` sheet 的欄位 3-4 為「可信度」「來源依據」。兩者來自 `AnalysisResult.meta` 的 `truth_level` 和 `source_labels`，是內部稽核用欄位。

[程式] `計算說明` sheet 已經有獨立的「可信度說明」區塊（第 932-945 行），用顏色圖例展示「精確/推導/估算/未知」。

### 建議：移至 `計算說明` sheet，`計算依據` sheet 只保留顏色標記

| 做法 | 說明 |
|------|------|
| **不建議** 直接刪除 | 內部稽核需要知道哪些行的重量是查表來的、哪些是估算的 |
| **不建議** 留在前兩欄 | 長官看了會問「這是什麼意思」 |
| **建議** 留在 `計算依據` sheet，但移到最後兩欄，並**只保留可信度顏色，不顯示文字** | 可信度欄用背景色標記（精確=綠、推導=藍、估算=黃、未知=紅），文字改為空或簡碼。來源依據移出 `計算依據`，只在 `計算說明` sheet 保留 |

### 詳細做法

```
計算依據 sheet：
  - 「可信度」欄 → 移到倒數第二欄，文字改為單字標籤（精/推/估/？）
  - 「來源依據」欄 → 直接移到「計算說明」sheet，不在計算依據顯示
  - 可信度顏色保留

計算說明 sheet（已存在）：
  - 現有的「可信度說明」區塊不動
  - 新增「各型號來源依據」對照表（型號 → 來源標籤）
```

[推測] 這樣計算依據仍然是完整的稽核底稿（有顏色可追溯），但長官拿到時可以把最後兩欄隱藏/刪除，得到一份乾淨的報告。

## 專業化介面建議

### 標題

[程式] `計算依據` sheet 的 A1 標題是「重量計算依據（逐項明細）」。

建議改為：
```
IEC 管架支撐 — 重量明細表
專案：{project_name}　　日期：{date}
```

### 表頭

- 表頭行高度至少 24pt，文字加粗、置中
- 表頭用深藍底白字（與現有 `_write_headers` 風格一致）
- 數量相關欄（單件數量、組數、總數量）用淺灰底標示，引導視線

### 凍結窗格

[程式] 已實作：`ws.freeze_panes = f"A{HEADER_ROW + 1}"` ✅ 不需改。

### 欄寬

[程式] 目前 `col_widths = [20, 8, 10, 18, 7, 14, 16, 14, 10, 14, 14, 10, 46, 13, 13, 14]`（16 欄）。

配合新建議順序，建議調整為：
```
型號 18 / 項次 6 / 品名 16 / 規格 18 / 材質 12 /
長度 8 / 寬度 8 / 屬性 8 / 物件類別 12 / 製造方式 12 /
單件數量 8 / 組數 6 / 總數量 8 / 單件重 10 / 單組重 10 / 合計重 12 /
計算式 48 / 可信度 8 / 來源依據 20
```

數量欄位（6~8 char）不必太寬。

### 數字格式

- 重量欄：`#,##0.000`（三位小數，千分位）
- 長度欄：`#,##0`（整數）
- 組數/數量：`#,##0`（整數）
- 可信度：文字，不必格式

### 小計 / 合計

[程式] 目前 `計算依據` sheet 沒有每型號小計和全案合計。

建議：
- 每個型號的末列加**型號小計列**（黃底，字體加粗）
- 全表末列加**全案合計列**（深藍底白字，字體加粗，與「長官統計」sheet 風格統一）
- 小計公式用 `SUBTOTAL(9, ...)` 配合篩選

### 顏色使用

| 用途 | 顏色 | 說明 |
|------|------|------|
| 表頭 | 深藍底白字 (`#1F4E78`) | 與現有風格一致 |
| 小計列 | 淺黃底 (`#FFF2CC`) | 醒目但不刺眼 |
| 合計列 | 深藍底白字 (`#1F4E78`) | 與長官統計一致 |
| 可信度標記 | 綠/藍/黃/紅 | 保留現有 `_CONFIDENCE_FILL` |
| 型號首列 | 淡藍底 | 目前 UI 已有，Excel 建議跟進 |
| 交替行 | 白/淺灰 | 長表格提高可讀性 |

### 哪些欄位應隱藏或放最後

| 處理 | 欄位 | 理由 |
|------|------|------|
| 放最後 | 零件ID、庫存ID | 內部用，長官不需看 |
| 放最後 | 可信度、來源依據 | 內部稽核用 |
| 放最後 | 物件類別、製造方式 | 採購用，長官不需看 |
| 保留中段 | 屬性 | 材料類別有助分類閱讀 |
| 保留中段 | 計算式 | 專業審查用，展現計算可追溯性 |

## 不建議採納

1. **不建議把「可信度」欄完全刪除**。它是內部稽核的重要資訊，移到最後即可。
2. **不建議把「計算式」欄刪除**。這是整個「計算依據」sheet 的核心價值——證明重量怎麼來的。長官可能不看，但審查時會看。
3. **不建議合併「計算依據」和「計算說明」為同一個 sheet**。Flat 資料表 + 靜態說明頁分開是正確設計，合併會毀掉樞紐分析。
4. **不建議在 UI 上隱藏零件ID/庫存ID**。開發者需要看到這兩個欄位做 debug，UI 不等於長官報表。
